The Raft consensus algorithm is designed to be understandable and equivalent to Paxos in fault-tolerance and performance. The primary difference lies in decomposed subproblems: leader election, log replication, and safety. A Raft cluster contains an odd number of servers (typically 5), allowing the system to tolerate 2 failures. At any given time, each server is in one of three states: Leader, Follower, or Candidate. In normal operation, there is exactly one leader and all of the other servers are followers. Followers are passive: they issue no requests on their own but simply respond to requests from leaders and candidates. The leader handles all client requests (if a client contacts a follower, the follower redirects the client to the leader). The third state, candidate, is used to elect a new leader.
