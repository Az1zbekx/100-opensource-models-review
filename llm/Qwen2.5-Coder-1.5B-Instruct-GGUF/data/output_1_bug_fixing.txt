Analyze the following Python banking transaction code. It has a critical concurrency flaw where concurrent transfers between two accounts can result in a deadlock or race conditions:

```python
import threading

class Account:
    def __init__(self, account_id: int, balance: float):
        self.account_id = account_id
        self.balance = balance
        self.lock = threading.Lock()

def transfer(from_acc: Account, to_acc: Account, amount: float):
    # Potential Deadlock: Thread 1 does transfer(A, B), Thread 2 does transfer(B, A)
    from_acc.lock.acquire()
    to_acc.lock.acquire()
    try:
        if from_acc.balance >= amount:
            from_acc.balance -= amount
            to_acc.balance += amount
            return True
        return False
    finally:
        to_acc.lock.release()
        from_acc.lock.release()
```

Your task:
1. Explain the exact mechanism of the deadlock vulnerability.
2. Provide the production-grade, thread-safe solution using lock ordering (acquiring locks in order of `account_id`) or context managers (`with`) to completely eliminate deadlock.
3. Write a test script with `concurrent.futures.ThreadPoolExecutor` demonstrating 100 concurrent bidirectional transfers without deadlocks.

1. **Deadlock Vulnerability Explanation**:
   - In the provided code, the `transfer` function acquires locks on both `from_acc` and `to_acc`. If the `from_acc` has a higher `account_id` than `to_acc`, the `from_acc` will acquire the lock on `from_acc` first, and then the `to_acc` will acquire the lock on `to_acc`. This sequence of lock acquisition creates a deadlock because both threads are waiting for the other to release the lock, and neither can proceed until the other releases the lock.
   - If the `from_acc` has a lower `account_id` than `to_acc`, the `from_acc` will acquire the lock on `to_acc` first, and then the `to_acc` will acquire the lock on `from_acc`. This sequence of lock acquisition also creates a deadlock because both threads are waiting for the other to release the lock, and neither can proceed until the other releases the lock.

2. **Thread-Safe Solution**:
   - To eliminate the deadlock, we can use lock ordering or context managers to ensure that the locks are acquired in a consistent order. Here, we will use lock ordering.
   - Lock ordering ensures that the locks are acquired in a consistent order, regardless of the order in which the threads are created. This prevents the deadlock by ensuring that the locks are acquired in the same order by both threads.
   - Here is the production-grade, thread-safe solution using lock ordering:
   ```python
   import threading

   class Account:
       def __init__(self, account_id: int, balance: float):
           self.account_id = account_id
           self.balance = balance
           self.lock = threading.Lock()

       def transfer(self, to_acc: 'Account', amount: float):
           with self.lock:
               with to_acc.lock:
                   if self.balance >= amount:
                       self.balance -= amount
                       to_acc.balance += amount
                       return True
                   return False
   ```

   ```python
               print(f"Transfer from account {result[0].account_id} to account {result[1].account_id} failed.")
   ```
